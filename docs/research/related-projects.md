# Related projects: what eleven GitHub repos offer Rouxtine

Researched 2026-10-29 at the owner's request. The owner found these eleven repos on GitHub and suspected most are abandoned or not applicable. Each repo was cloned read-only and read at the commit named in its source entry; a second pass re-checked licence, last commit, activity, verdict and every contradiction claim. `[n]` refers to the numbered sources at the bottom. **This is research, not legal advice.**

Path prefixes name the repo at the commit in its source entry: `VCT:` tdecker91/visualcube [1], `VCR:` Cride5/visualcube [3], `BC:` briefcubing [5], `M2P:` min2phase [10], `AT:` Alg-Trainer [14], `P15:` 15Puzzle_OptimalSolver [16], `CC:` chronocube [18], `CS:` cubesplit [19], `MT:` midori-timer [20], `RR:` rouxers/book [23], `ACN:` alg.cubing.net [24], `CJS:` cubing.js [25]. A bare `src/...` path is nauroth/roux-trainers, as in HANDOFF.md [28]. `scope.md`, `HANDOFF.md` and `rouxtine-design.md` are in `docs/`; the other note names are in `docs/research/` [29][30].

## Summary

- **The owner's guess is half right.** Nine of the eleven have had no code change since mid-2024 or earlier. Only briefcubing (commits April–July 2026, a GAN Gen4 pull request in October 2026) and alg.cubing.net (frozen, but redeployed in June 2026 and still live) show recent life [5][6][24].
- **Dormant is not the same as useless.** Two repos are direct inputs:
  - **min2phase** is finished code that csTimer and the web app already rely on. Vendor its five Java files unchanged for random-state scrambles, under its MIT grant [10].
  - **The Roux Reader** (rouxers/book) is MIT text and example data for the technique library, several R1 lessons and two case sets [23].
- **Five give ideas only:** tdecker91/visualcube (the CMLL plan-view thumbnail), briefcubing (smart-cube case drills), Alg-Trainer (case-module options), cubesplit (split roll-ups and deltas), alg.cubing.net (recon URL import, Twizzle export).
- **Two are reference only:** Cride5/visualcube (parameter docs, mask strings) and midori-timer (one licence fact about onionhoney).
- **Two are skips:** chronocube (a basic 2016 timer) and 15Puzzle_OptimalSolver (a sliding-puzzle solver whose main technique does not work on a cube).
- **Licences block nothing we plan to take.** cubesplit and 15Puzzle have no licence, Alg-Trainer's and briefcubing's alg data are third-party compilations, and tdecker91's ISC label conflicts with its inherited LGPL. In each case we take ideas only, or write fresh code.
- **Existing notes needed small fixes**, applied on 2026-10-31 (details in "What changes in our plans"): roux-training-features.md §2 (CaseVisualizer is a third-party wrapper), the min2phase licence in roux-training-features.md and monetization.md, roux-community-resources.md §6.1, §7, §8.6 and §10, and training-regimens.md §4.

## 1. tdecker91/visualcube

- **What it is.** VisualCube TS, published on npm as `sr-visualizer`. A browser TypeScript library (svg.js 2.7.1, webpack 5) that draws an NxN cube as SVG or PNG from an options object: alg or case, facelets, stage mask, colour scheme, viewport rotations, plan view, opacity, arrows [1][2]. It is a git fork of Cride5/visualcube; the PHP was removed in `f302c82` on 2018-12-30 [1]. The web app's case thumbnails come from it: `src/components/CaseVisualizer.tsx` (41 lines) calls `SRVisualizer.cubeSVG` with view `plan`, the inverse of the alg, mask `cmll` or `coll`, and a colour remap. `package.json:36` asks for `^1.0.8` and the lockfile pins 1.0.8 (`package-lock.json:23536-23542`) [28].
- **Status.** Dormant. Last commit `220b429` on 2022-05-31; npm 1.0.13 the same day [1][2]. 96 commits: 34 come from the inherited Cride5 history (Conrad Rider 29, Logiqx 3, Jaume Casado Ruiz 2), and the fork's own 62 are all by Tyson Decker, in bursts: Dec 2018–Feb 2019 (45), Jul–Aug 2019 (3), Aug 2021 (9), Feb 2022 (4), May 2022 (1) [1]. 51 stars, 4 forks, 0 open issues [27]. Drawing and masking barely changed after 1.0.8 (`ac907da`, 2019-08-02): `drawing.ts` by 5 lines, `masking.ts` by 2 [1].
- **Licence.** Unclear label. `VCT:package.json:13` says ISC, and its `files` list names a `LICENSE` that does not exist. The repo still carries `COPYING` (GPL-3.0) and `COPYING.LESSER` (LGPL-3.0), byte-identical to Cride5's. No file under `src/` has a header. `VCT:README.md:10-14` says "Most of the original Author's logic remains the same" [1]. Treat it as LGPL-3.0-or-later code by Conrad Rider plus additions by Tyson Decker labelled ISC.
- **GPL-3.0-only fit.** Yes. Ideas and geometry constants need no notice. LGPL-3.0 "incorporates the terms and conditions of version 3 of the GNU General Public License, supplemented by the additional permissions" (`COPYING.LESSER:9-11`), and GPLv3 s.7 lets whoever conveys a copy "remove any additional permissions from that copy" (`COPYING:354-356`) [1]. So a Kotlin file translated from this code can be GPL-3.0-only if it keeps "Copyright (C) 2010 Conrad Rider", credits Tyson Decker, says it was modified, and is listed on the Licences screen.
- **Verdict: borrow ideas.** It is the readable spec for the CMLL/NMCLL plan-view thumbnail that users know from the web app. It is not a model for the interactive cube: fixed Euler-angle camera, faces sorted as wholes, no layer turns [1].
- **What to take.**
  - Plan view is the normal projector plus a rim. `VCT:src/cube/geometry.ts:87-98` sets viewport rotation `[[X, -90]]` for `plan`; `VCT:src/cube/drawing.ts:244-272` (`renderOLLStickers`) draws the top row of R, F, L and B as quads pushed out by 0.2 × the face normal and shrunk to 0.94. One static projector can then feed both 3D and plan thumbnails, instead of a separate hand-drawn top view like `src/components/CubeSim2D.tsx:11-78` [1][28].
  - The static projection is cheap enough for a grid of 42 CMLL cards: grid points per face (`geometry.ts:32-49`), centre and scale by 1/N, Euler rotations, translate z by 5, project with x·d/z (`VCT:src/math.ts:39-64`); faces sorted by the z of their rotated normal (`drawing.ts:75-80`) and culled at z ≥ -0.105 (`drawing.ts:96-98`) [1]. In Compose, build the paths once in `Modifier.drawWithCache`.
  - The familiar look: stickers inset to 0.85 (`drawing.ts:165-169`), black outline at 0.94 (`drawing.ts:132-145`; `index.ts:18-36`), default view y45 then x-34 with distance 5 (`index.ts:22`, `:27`), mask colour #404040 (`colors.ts:3`) [1].
  - `VCT:src/cube/options.ts:6-35` (`ICubeOptions`) is a good template for an immutable Kotlin `CubeImageSpec`. Keep its split between alg and case (case = inverse alg) [1].
  - The mask greys the solved-state stickers first and only then applies the alg or case (`VCT:src/cube/stickers.ts:47-69`), so the grey follows the pieces. `maskAlg` turns the mask without moving colours (`stickers.ts:13-20`), so one mask can serve the M-hand mirror and x2y orientations [1].
  - Masks are per-face predicates (`VCT:src/cube/masking.ts:10-195`); only `cmll` (`:127-134`) and `f2b` (`:179-186`) are Roux masks [1]. Rouxtine's masks stay piece-level, from `src/lib/CubeLib.tsx:777-873` [28]. These two sticker patterns make cheap golden fixtures for the piece-to-sticker mask code.
  - Sticker states beyond grey: `n` (blank), `o` (oriented, grey) and `t` (transparent) (`VCT:src/constants.ts:4-14`, `:68-72`) [1]. "Oriented" suits EO-only views for EO and EOLR; "transparent" gives a "show only this stage" view.
  - Arrows (`VCT:src/cube/models/arrow.ts`; `drawing.ts:277-345`): from, to, optional via point, scale 0–20, influence 0–50, colour; a quadratic curve, stroke 0.12/N with round caps, a triangular head [1]. Useful for 4c/EP arrows and the R2+ item "CMLL→LSE effect on alg cards" (scope.md R2+ item 5). In Compose: `Path.quadraticTo` plus a round-cap `Stroke`.
  - Leave out svg.js rendering, `cubePNG` (`index.ts:49-74`), the sticker simulator (`simulation.ts`) and the URL parser (`parsing/options.ts`) [1].
- **Risks.**
  - The licence label conflicts with the history. Write the Kotlin renderer fresh from these notes; do not translate functions (HANDOFF "Don't": it would add copyright holders to the Play question).
  - Bugs to avoid when reading it as a spec [1]: `renderArrow` takes s2's and s3's positions from s1's face (`drawing.ts:292-293`, `:309-310`), so arrows across faces are wrong (Cride5's `gen_arrow` is right). A mask suffix such as `stage=f2b-y` is passed through as the mask name and throws (`parsing/options.ts:29-31`, then `masking.ts:198-200`). `parseInt(v) || 100` makes opacity 0 impossible (`parsing/options.ts:54`, `:57`). The arrow regex (`parsing/arrow.ts:10`) accepts `-s` only before `-i` and uses a one-character class, so scale or influence above 9 cannot be parsed from a string. `ac` and `trans` are not implemented (`parsing/options.ts:68-71`).
  - Faces are ordered URFDLB; the web app and our model use UDFBLR (remap in `src/components/CaseVisualizer.tsx:22-30`) [28]. Remap any copied fixture.
  - No upstream to follow.
- **Against existing notes.**
  - roux-training-features.md §2 (the 2D/3D cube view row) lists `CaseVisualizer.tsx` next to `CubeSim2D.tsx` as the web app's 2D CMLL visualiser to reuse. CaseVisualizer only wraps the npm package, so it holds no onionhoney drawing code to port. Only CubeSim2D.tsx is onionhoney's own [28][30].
  - licensing-monetization.md §2.3 lists vendored third-party code (min2phase, three.js). Leaving out sr-visualizer is accurate, because it is an npm dependency. Still, the web app's case thumbnails are Conrad Rider's and Tyson Decker's code, which the onionhoney authorship finding does not cover [30].
  - android-ui-stack.md §2 ("Rendering the virtual cube") describes masked stickers as "a grey fill with a coloured border". That is CubeSim.tsx; the case thumbnails use this library's flat #404040 [1][30].

## 2. AshleyF/briefcubing

- **What it is.** Brief Cubing (briefcubing.com, footer v0.1.6, live on 2026-10-29) by Ashley Feniello [5][7]. A static web alg trainer for Web Bluetooth smart cubes. It shows a random case; you solve it on the cube; the app applies your moves to its own virtual copy of the case, so the physical cube never needs setting up (the README says it can be "blank with stickers removed") [5]. It times recognition and execution separately. Mostly CFOP; the Roux sets are CMLL, 2-look CMLL, EO, 4c (labelled "L4E") and second-block last-pair inserts, with no EOLR [5].
- **Stack.** Plain JavaScript with no build step, jQuery 1.11.1 and jQuery Mobile 1.4.5, NoSleep.js, lz-string, a colour picker and a Google Analytics tag [5].
- **Status.** Alive, but changes rarely. Last commit `ce43db4` on 2026-07-15 [5]. 163 commits since 2018-09-29: 2018 62, 2019 58, 2020 5, 2021 25, 2022 3, none in 2023–2025, 2026 10 (9 in April, 1 in July) [5]. One maintainer, with merged code from outside authors: kliu99 (12 commits, PRs #12–#14, 2021), ExcuseMi (2, PRs #8–#9, 2020) and Khoa Nguyen (1, PR #10, 2021) [5]. 31 stars, 8 forks; 7 open issues (newest #19, "Add support for GAN 356 i3", 2024-09-15) and 2 open PRs: #20 (egga22, 2026-10-09, GAN Gen4) and #18 (mlg404, 2023-11-17, Brazilian Portuguese) [6][27].
- **Licence.** The repo is MIT, "Copyright (c) 2018 Ashley Nathan Feniello", added through PR #2 (merge `3031e68`, 2019-02-12) [5]. But `BC:btcube.js:1-2` says it modifies lgarron's cuble.js and csTimer's GAN decryption [5]. csTimer is GPLv3 [9]. cuble.js was MIT when its licence file appeared (`80a47c7`, 2018-07-13) and became GPL-3.0-or-later in `edd5f2c` on 2018-09-03 [8]. briefcubing's cuble.js-derived `giiker.js` first appeared on 2018-09-29 (`6b7d044`), and was renamed `btcube.js` in `e2fabdc` (2019-06-05) [5]. Which cuble.js snapshot was copied is unknown, but the csTimer part alone makes `btcube.js` GPL-derived. The sounds, `Hotdog.gif` and stamp images have no stated source [5].
- **GPL-3.0-only fit.** MIT code: yes, with its notice. `btcube.js`: compatible as GPL code, but it must never be described as MIT. We take ideas only, so nothing goes on the Licences screen.
- **Verdict: borrow ideas** for smart-cube case drills (scope.md R2+ item 1). Skip the Bluetooth code: smartcube-web-bluetooth covers more protocols, better (smart-cubes.md §6) [30].
- **What to take.**
  - *Case solved in the app.* The start state is the alg applied in reverse to a solved cube (`BC:ui.js:532-588`; `BC:cube.js:305-312`). Incoming face turns are added to it (`ui.js:289-311`). The physical cube's state is never read [5]. This could be an optional "execution drill" input next to "scramble the real cube". The trade-off: you recognise the case on screen, not on the cube.
  - *Solved check without slice merging.* After each move it compares the state with a pattern in all 24 whole-cube orientations (`ui.js:272-288`). Patterns name pieces by face letter, with `.` as a wildcard (`cube.js:500-515`; `algs.js:4-6`). A leftover AUF, a leftover M2 (as L2 R2) and a leftover M or M' (as L' R or L R') are accepted (`ui.js:214-238`) [5]. So a case drill never has to merge L + R' into M. If we reuse the matcher, add the check it lacks: two face letters must not map to the same colour.
  - *Settle window.* A state is checked only after 50 ms with no new move, using a queue counter (`ui.js:260-311`) [5]. That also covers the two halves of a slice turn.
  - *2-look CMLL partial state.* "Partial" patterns (corners oriented, not permuted) mark a half-solved state in amber and let you retry from it (`ui.js:182-186`, `:245-258`; `algs.js:136-231`) [5]. Useful for the BEG 2-look CMLL drill.
  - *Turning the cube as a control.* After a result, a clockwise turn means Next and an anticlockwise turn means Retry, accepted only 600 ms after the last move (`ui.js:262-270`). Four identical turns in a row skip the case (`ui.js:289-303`). The Tips text says U and U', but any face works (`BC:index.html:504-513`) [5].
  - *Timing.* Recognition runs from "case shown" to the first move, execution from the first move to solved (`ui.js:23-105`). The shown average is the mean of the last 5, ignoring anything of 10 s or more (`ui.js:48-62`). A no-progress timeout (0.5–10 s, or off) marks a fail (`ui.js:3-9`; `index.html:488-490`) [5]. This matches what training-regimens.md already plans [30].
  - *Per-case AUF.* Tapping the cube centre cycles the starting AUF and saves it per alg (`ui.js:663-689`) [5].
  - *Colour neutrality.* You pick the up colours and the app adds a random y (`ui.js:551-563`). For CMLL it scrambles the M slice and U layer so the edges do not give the case away (`ui.js:568-576`) [5]. Our random-state stage scrambles already do the second part.
  - *Not worth copying.* Case order "weighted by incorrect" uses weight 1 − correct/(total+1) (`ui.js:598-620`), so a case you always get right drifts towards zero weight; FSRS-6 is better [5]. The Roux alg lists (`algs.js:682-871`: 2-look CMLL 9, CMLL 42, EO 11, 4c 23, SB front 47, back 47) come from other sites; onionhoney's data is the better source [5]. `BC:cases/cmll.html` (a 4-angle CMLL recognition sheet) and `BC:colors/corners.html` (a 48-case hidden-sticker quiz) are evidence for CMR's per-angle display and a possible colour-scheme warm-up; write our own [5].
  - *Protocol code, skip.* Giiker/Mi, GAN Gen1 with only 2 of csTimer's keys (newer cubes named "GAN…" take this path and fail), GoCube/Rubik's Connected, and the Monster Go 3Ai over GAN Gen2 (`btcube.js:22-28`, `:595-644`). No QiYi, MoYu or GAN Gen3, and no cube timestamps. `btcube.js:349` has an assignment bug: `if (len = 8 && ...)` [5]. PR #20's Gen4 driver reads one move per notification, ignores timestamps and fills gaps with history requests [6]; SWB's Gen4 driver is the better source.
- **Risks.**
  - The MIT label hides GPL-derived Bluetooth code. Never cite `btcube.js` as MIT.
  - On-screen recognition trains a different skill from recognition on the cube. Label the mode and keep its stats separate.
  - Turn gestures can fire during regrips or AUFs; the only guard is 600 ms. Rouxtine needs a setting to turn them off.
- **Against existing notes.** No note mentions briefcubing [30]. It confirms smart-cubes.md §3.2 (Monster Go 3Ai uses GAN Gen2) and refines smart-cubes.md §3.5: slice merging is needed for reconstructions and splits, not to judge a case drill [5][30].

## 3. cs0x7f/min2phase

- **What it is.** Chen Shuang's Java implementation of Kociemba's two-phase 3x3 solver, the one behind csTimer, TNoodle and (via cubing/min2phase.js) the web app [10][30]. It turns a 54-character facelet string into a face-turn solution of about 20 moves in about 1 ms after table init; with `INVERSE_SOLUTION` it returns a scramble for that state (`M2P:src/Search.java:175-192`; `M2P:README.md:61-64`) [10]. Five files, 2,470 lines, using only `java.util` and `java.io` (`Tools.java:3-6`; `CubieCube.java:3`) [10].
- **Status.** Dormant but finished. Last commit `4d183b9` on 2023-02-21 (README only, "Add MIT license"); last source change 2019-06-30 [10]. 120 commits since 2012-06-29: 2012 5, 2013 4, 2014 24, 2015 39, 2016 1, 2017 25, 2018 10, 2019 11, 2023 1. All code is by Chen Shuang; the only outside commit is README-only (PR #10) [10]. Only PR #16 is open (2022-08-24, removes `synchronized`, unsafe); #3, #11 and #18 were closed unmerged; #1 and #10 were merged [11]. 344 stars, 66 forks, 6 open issues and PRs [27]. Branches `dev` and `dev-min` are ancestors of master; `full_phase1` and `two-leg-rtm` are research forks [10].
- **Licence.** Dual: GPL-3.0-or-later or MIT, at the licensee's choice. `M2P:README.md:106-121` has a GPLv3 section that dates from the first commit (`2d2d1ae`, 2012-06-29); `README.md:123-143` added "License MIT", "Copyright (c) 2023 Chen Shuang", in `4d183b9` [10]. Only `src/Search.java:1-16` has a file header (GPL-3.0-or-later, "Copyright (C) 2015 Shuang Chen"); the other four files have none, and no commit on any branch has a LICENSE or COPYING file [10]. The first commit's BSD-style header was replaced the same day (`24257be`) [10]. `M2P:example/MainProgram.java:14-22` carries a Jigloo "not for commercial purpose" notice [10]. The sibling min2phase.js has the same dual README and says `(MIT or GPL-3.0)` [12].
- **GPL-3.0-only fit.** Yes under either branch. Take it under MIT: Chen Shuang wrote all the code, so the README grant is effective. Keep Search.java's header unchanged, put the MIT text (citing `4d183b9`) in the module NOTICE and on the Licences screen, and add a modification notice to any file we change. Under MIT, a future s.7 Play Billing permission needs nothing from Chen Shuang; it still needs onionhoney's.
- **Verdict: port code**, meaning vendor the five Java files unchanged into a plain `java-library` Gradle module `:min2phase`. A Kotlin rewrite of 2,470 lines of bit-twiddling code (signed shifts, `char` as unsigned table cells, packed pruning tables) would buy nothing and risk subtle bugs. The files build for minSdk 24 with no desugaring and no reflection, and run in fast JVM tests.
- **What to take.**
  - `src/{Search,CoordCube,CubieCube,Tools,Util}.java` from `4d183b9`. Not `example/` or `test/` [10].
  - Call it through a small Kotlin `ScrambleGenerator`: `Search().solution(facelets, 21, probeMax, 0, Search.INVERSE_SOLUTION)`. Failures come back as strings `Error 1`…`Error 8`, not exceptions (`Search.java:165-173`). Errors 1–6 (parity, twist, flip) double as a validity check for our own sampler in tests [10].
  - Facelet order is U, R, F, D, L, B, nine each (`README.md:67-91`). Colours are read through the six centres (`Search.java:240-269`), so any six distinct characters work [10]. We need one adapter from our ported `CubieCube`, like roux-trainers' `to_cstimer_cube()`.
  - Full-solve scrambles: `Tools.randomCube(Random)` (`Tools.java:173-179`) draws from the Random it is given, and the search is deterministic, so a seeded Random gives the same scramble on every device [10]. Use `SecureRandom` for ordinary scrambles (`Tools.java:159-161`).
  - Masked states: `Tools.randomState(cp, co, ep, eo, gen)` is `protected`, with -1 meaning "random" (`Tools.java:265-315`) [10]. Rouxtine must sample centres too, so keep our own port of `get_random_with_mask` (`src/lib/CubeLib.tsx:1006`) and use min2phase only to solve. Do not expose its CFOP/ZB helpers (`Tools.java:318-380`).
  - Centres: min2phase knows face moves only (`Tools.java:405-435`). For a state whose M-slice centres are off by M^k, apply M^-k, solve, then append M^k. roux-trainers handles only M2 (`src/reducers/CmllStateM.tsx:13-26`, `:245-258`) [28]. Generalise to M, M' and M2 for SB, CMLL, LSE, EOLR and MC states.
  - What it cannot do: restrict the move set. Output is always a full-face scramble of up to 21 moves. Keep roux-trainers' short option (stage solver's solution inverted plus a margin, `src/reducers/BlockTrainerStateM.tsx:113-141`) [28].
  - Memory: static tables of about 1.1 MB for the process lifetime (`CoordCube.java:23-39`; `CubieCube.java:29-61`), matching "about 1MB" (`Search.java:23`) [10].
  - Init: the first `solution()` runs a partial init; `Search.init()` runs the full one (`Search.java:188`, `:235-238`). Desktop figures: full init 195 ms, partial 60 ms; per solve 0.685 / 0.805 / 4.62 ms for unlimited / 21 / 20 moves after full init (`M2P:Benchmark.md:5-9`) [10]. There are no Android figures. Init on a background dispatcher at app start or first trainer entry, prefetch the next scramble, and measure on a low-end device.
  - Do not ship the tables as an APK asset (`Tools.saveTo` / `initFrom`, `Tools.java:73-153`): it adds about 1 MB, and GPL s.1 would then require shipping the generator [10].
  - Output has double and trailing spaces (`Util.java:98-101`, `:152-173`). Collapse whitespace before storing or exporting to Twisty/Cubic Timer [10].
  - If `randomState` is ever used with a seeded Random: `resolveOri` and `resolvePerm` draw from the static `Tools.gen`, not the argument (`Tools.java:185`, `:217`, `:228`), so the result is not reproducible. A 3-line fix, with a modification notice. `randomCube` is not affected [10].
  - Threading: `solution()` and `next()` are synchronised per instance and init is `static synchronized`, but the init flags are plain statics (`Search.java:175`, `:213`, `:235`; `CoordCube.java:46`) [10]. Use one `Search` per worker after a completed `Search.init()`. Do not apply PR #16.
  - Later, for smart-cube scramble guidance: solve T⁻¹·C (target T, live state C) and re-plan after each wrong move.
  - Do not use TNoodle's Maven copy (`scrambler-min2phase` 0.19.2: an older copy with the GPLv3-only README) or the JavaScript ports [13].

  - Mask strings in URFDLB order (`visualcube.php:351-428`). `cmll` (`:397-399`) = `101000101 101111111 101101101 101101101 101111111 101101101`; `f2b` (`:415-417`) = `000000000 000111111 000101101 101101101 000111111 000101101`. After remapping to UDFBLR, both are golden fixtures for our mask expansion. There is no FB-only, SB, SS, LSE, EO or 4c mask, so onionhoney's masks stay the source [3][28].
  - Mask rotation suffix, e.g. `stage=cross-x2` (`visualcube_api.php:196-199`; `visualcube.php:345-350`, `:442-446`): one mask reused under a rotation, for M-hand and colour-neutral orientations [3].
  - Arrows: `parse_arrow` (`visualcube.php:665-699`) takes influence, scale and colour in any order; `gen_arrow` (`:844-876`) uses each sticker's own face, so it is the correct reference for arrows across faces [3].
  - Named palettes and schemes (`visualcube.php:115-172`, `:129-133`) suggest named colour-scheme presets in settings [3].
- **Risks.** Nothing can be reused as code. Never put VisualCube image URLs in Rouxtine content or exported sheets: the host shows an error. The `line` mask is easy to mistake for a Roux mask.
- **Against existing notes.** roux-community-resources.md §7 (the VisualCube row) lists `f2b`, `cmll` and `line` as masks of interest. `line` (`visualcube.php:418-420`) covers DF, DB and the F/D/B centres: ZZ's EOLine, not a Roux line [3][30]. The rest of that row holds.

## 11. cubing/alg.cubing.net

- **What it is.** Lucas Garron's alg and reconstruction viewer/editor (AngularJS, twisty.js on Three.js, a jison alg parser). All state lives in the URL: `alg`, `setup`, `type`, `stage`, `puzzle`, `scheme`, `title`, `view` [24]. The README says development is frozen, "v2" is the Twizzle editor in cubing.js (`ACN:README.md:1-8`), and traffic will eventually redirect there (`:56-59`). On 2026-10-29 it still served v1 (HTTP 200, `VERSION.txt` = `a4423df`) with an "Open in Twizzle" button [24].
- **Status.** Frozen but deployed. 386 commits since 2012-02-28, 376 by Lucas Garron, 269 of them in 2013–2014. Frozen since `6e126b5` (2021-07-03); since then 17 Twizzle-link commits in 2022, 2 CDN updates in 2024 and 4 maintenance commits in 2026 (last `c245b37`, 2026-06-04) [24]. 206 stars, 36 forks, 95 open issues and PRs; the description now reads "Superseded by Twizzle" [27]. Twizzle in cubing.js is active (HEAD `6157191`, 2026-10-24) [25].
- **Licence.** MIT, "Copyright (c) 2014 Lucas Garron" (`ACN:LICENSE.md:1-22`); bundled twisty.js and alg.js are MIT, Font Awesome fonts OFL (`:25-36`) [24]. cubing.js is "MPL-2.0 OR GPL-3.0-or-later" (`CJS:package.json:6`) [25].
- **GPL-3.0-only fit.** Yes. URL formats and notation are interoperability facts, so a clean Kotlin importer needs no notice. If the escape functions or the grammar are ported line by line, keep the MIT notice. Take cubing.js for ideas only (HANDOFF "Don't"); the URL format needs no code.
- **Verdict: borrow ideas** for REC import (scope.md R2+ item 2) [29]. Not for rendering: twisty.js, Three.js and WebView are out (HANDOFF.md "Virtual cube").
- **What to take.**
  - *URL codec* (`ACN:src/alg.cubing.net/alg.cubing.net.js:295-320`). After percent-decoding: `-` → `'` then `&#45;` → `-`; `+` → space then `&#2b;` → `+`; `_` → space then `&#95;` → `_` [24]. A plain decoder turns `2-3Rw` into `2'3Rw`. About 20 lines of Kotlin, with round-trip tests.
  - *Parameters* (`alg.cubing.net.js:80-230`). `type` decides the anchor: `moves` and `reconstruction` mean setup is the start state; `alg` and `reconstruction-end-with-setup` mean setup is the end state, so the start is setup + inverse(alg) (`:116-161`). Only non-default values are written, and `fbclid` is stripped (`:322-358`) [24].
  - *Notation grammar* as the spec and test list for our parser (`ACN:src/alg.cubing.net/twisty.js/alg/alg_jison.jison:1-143`): `//` and `/* */` comments, `.` pauses, `(…)n` groups, `[A, B]` commutators, `[A: B]` conjugates, `Rw` and `r`, slices, rotations, layer prefixes and timestamps [24]. For 3x3 Roux, reject big-cube layer moves.
  - *Test vectors:* the three README links at `README.md:27-29` (a multi-line WR reconstruction, an alg-type T-perm, the Notation Stress Test) [24].
  - *Gap in the code we port:* `src/lib/CubeLib.tsx:467-508` (`MoveSeq.parse_line`) strips only `//` comments and reads letter by letter, so letters inside `/* Scramble */` become moves, `Rw` becomes `R`, and groups and commutators are flattened, not expanded [28]. REC import needs the fuller grammar.
  - *Metric and mirror tables* (`twisty.js/alg/alg.js:578-651`): its `btm` is STM on 3x3, `obtm` is HTM; the M mirror map is the M-hand mirror [24].
  - *Defect, do not copy:* `alg.cubing.net.js:383` tests for type id `algorithm`, but the id is `alg` (`:140`), so "Open in Twizzle" drops the end anchor for alg links [24]. Apply the type rule ourselves.
  - *Twizzle side:* the editor reads `alg`, `setup-alg`, `setup-anchor`, `puzzle`, `stickering`, `title` and more (`CJS:src/cubing/twisty/views/twizzle/url-params.ts:119-129`), remaps the old `experimental-*` names (`CJS:src/sites/alpha.twizzle.net/edit/main.ts:24-28`), and still emits `experimental-stickering` itself (`CJS:src/cubing/twisty/model/TwistyPlayerModel.ts:273`) [25]. Accept both spellings.
  - *Export target:* `https://alpha.twizzle.net/edit/?setup-alg=…&alg=…&title=…` with `// FB`, `// SB`, `// CMLL`, `// LSE` comments. Per-step links can use the Roux stickerings `FirstBlock`, `SecondBlock`, `CMLL`, `L10P`, `L6E`, `L6EO` (`CJS:src/cubing/puzzles/stickerings/puzzle-stickerings.ts:44-49`) [25]. On 2026-10-29 `twizzle.net/` redirected (307) to `alpha.twizzle.net/` and `twizzle.net/edit/` returned 404, so alpha is still the editor host [26].
  - *Android intake* (our suggestion, not from the repo): paste plus an `ACTION_SEND` text share target, parsed offline. App Links are not an option for domains we do not own, which fits rouxtine-design.md §7 (App Links only for our own `nauroth.github.io`).
- **Risks.** Twizzle is still "alpha" and has renamed its parameters once; test against live links. Naive decoding silently corrupts algs. Do not bundle AngularJS, twisty.js, Three.js or Font Awesome.
- **Against existing notes.** roux-community-resources.md §7 (the alg.cubing.net row) is confirmed [30]. Two precisions: alg.cubing.net does not redirect yet, so scope.md R2+ item 2 is right to list it as its own format [24][29]; and `setup=` / `alg=` are alg.cubing.net's parameters, while Twizzle uses `setup-alg` plus `setup-anchor=end` for end-anchored algs [25].
